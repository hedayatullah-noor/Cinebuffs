🎬 Project Overview
CineBuffs — movie/series/blog review platform, built with:

Framework: Next.js 15.1.6 (App Router) + React 19 + TypeScript
DB: MySQL via Prisma ORM (@prisma/client 6.19)
Auth: Custom JWT sessions via jose (httpOnly cookie), bcrypt/bcryptjs for hashing
Styling/UI: Tailwind v4, Framer Motion, Lucide icons, React Quill (rich text editor)
Email: Nodemailer (forgot-password flow)

🗂️ Structure

Public pages: home, movies, series, blog, reviews/[slug], about, contact, contributors, subscribe
Auth pages: login, signup, forgot-password, reset-password
Dashboards: /admin (full CRUD + user role management), /moderator (review approval)
Data model (Prisma): User (role: ADMIN/MODERATOR/USER), Review (status: PENDING/APPROVED/REJECTED, two-image system — poster + slider), Comment, Subscriber

Achha structured hai overall — proper separation of concerns, App Router conventions follow ho rahe hain, reasonably clean component breakdown (ReviewCard, ReviewGrid, HeroSlider, GenreDropdown, etc).
🚩 Serious issues I noticed (important — please fix before going fully live)
1. Unauthenticated admin endpoints — inconsistent auth checks across admin routes:

/api/admin/reviews (GET + PATCH) — koi bhi is route ko hit karke pending/rejected reviews dekh sakta hai aur review status approve/reject kar sakta hai, bina login ke
/api/admin/stats — site stats leak ho rahe hain publicly
/api/admin/subscribers — newsletter subscriber emails publicly exposed

Compare karo /api/admin/users se — wahaan getSession() + role !== 'ADMIN' check hai, lekin baaki admin routes mein yeh check missing hai. Yeh add karna zaroori hai.
2. Debug/leftover routes still in production code:

/api/dump — raw SQL query pe entire Review table dump karta hai, no auth
/api/debug-user — admin user info leak karta hai
/api/set_admin_pass — GET request pe kisi bhi email ko admin bana deta hai with a hardcoded password, sirf hitting the URL se
/api/generate — execSync("npx prisma generate") run karta hai server pe, no auth
/api/migrate, /api/migrate_real_data, /api/clean-wp — data-wiping/migration routes, publicly GET-accessible

Yeh sab dev/debugging ke liye bane the shayad, but agar yeh production mein deployed hain toh koi bhi inhe hit karke database wipe/manipulate kar sakta hai. Strongly recommend: inhe delete kar do ya at least admin-auth guard laga do, aur agar set_admin_pass wala password kahin use hua hai woh rotate/change kar do.
3. JWT fallback secret: auth.ts mein process.env.JWT_SECRET || 'fallback_secret_for_dev_only' — agar .env mein JWT_SECRET set nahi hai production mein, sessions ek known/public secret se sign ho rahe honge.
4. prisma.$queryRawUnsafe / $executeRawUnsafe used in a couple of places (dump, migrate) — inherently risky if any user input ever gets near them (currently no input, so low risk today, but worth avoiding).
Baaki code quality ki baat karein toh solid hai for a diploma-level fresher project — modern stack use kiya hai, App Router, Prisma, JWT sessions properly (mostly) implemented. Yeh security gaps fix karna easy hai aur resume/interview ke liye bhi acha talking point ban sakta hai ("I found and fixed security vulnerabilities in my own app").
